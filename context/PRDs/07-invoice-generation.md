# PRD 07 — Invoice Generation

> **Feature Area**: PDF Invoice Generation & Download
> **Phase**: Phase 2
> **Priority**: Medium
> **Dependencies**: PRD 04 (Billing Cycles & Bill Splitting), PRD 03 (Tenant Management)

---

## 1. Overview

FairSplit allows owners to generate professional PDF invoices for tenants summarizing their share of utility bills within a billing cycle. Invoices are generated on-demand using `@react-pdf/renderer`, streamed directly to the browser, and are not persisted in storage. Each invoice contains line items for every bill in the cycle, the tenant's person-days breakdown, and a total amount owed.

---

## 2. Goals

- Provide owners with a one-click way to generate invoices for tenants in a cycle
- Give tenants the ability to download their own invoice for record-keeping
- Produce clean, professional PDF documents with consistent branding
- Keep the system simple by generating invoices on-demand rather than storing them

## 4. Invoice Content Specification

### Header Section

| Field | Source | Example |
|-------|--------|---------|
| Invoice Number | Generated | `INV-575M-SO25-ANIL` |
| Date Generated | Current date (UTC) | `January 15, 2026` |
| Property Name | `properties.name` | `575 McKinney` |
| Property Address | `properties.address_line1, city, state, zip` | `575 McKinney, McKinney, TX 75070` |
| Owner Name | `profiles.full_name` (property owner) | `Shekar` |
| Cycle Label | `billing_cycles.label` | `Sept - Oct` |
| Cycle Status | `billing_cycles.status` | `Closed` |

### Recipient Section

| Field | Source | Example |
|-------|--------|---------|
| Tenant Name | `profiles.full_name` or `property_tenants.display_name` | `Anil` |
| Tenant Email | `profiles.email` | `anil@example.com` |
| Occupancy Period | `property_tenants.join_date` to `leave_date` or "Present" | `Jan 1, 2025 - Oct 30, 2025` |

### Line Items Table

| Column | Description | Example |
|--------|-------------|---------|
| # | Row number | `1` |
| Category | Bill category (capitalized) | `Electricity` |
| Provider | Bill provider name | `CoServ` |
| Service Period | `service_start_date` to `service_end_date` | `Sep 15 - Oct 14, 2025` |
| Bill Total | Full bill amount (formatted dollars) | `$276.00` |
| Days Present | Tenant's person-days for this bill | `30` |
| Total Person-Days | Sum of all tenants' person-days | `62` |
| Your Share | Tenant's calculated amount | `$133.55` |

### Summary Section

| Field | Calculation | Example |
|-------|-------------|---------|
| Total Bills in Cycle | Count of line items | `3` |
| Total Cycle Amount | Sum of all bill amounts | `$504.42` |
| **Your Total Share** | Sum of tenant's share across all bills | **$231.37** |

### Footer

- "Generated by FairSplit" branding text
- "This invoice was generated on {date}. Amounts are calculated using the person-days method."
- Small disclaimer: "This is a summary of shared utility costs and is not a legal invoice."

## 5. Invoice Numbering

### Format

```
INV-{propertyShort}-{cycleShort}-{tenantShort}
```

### Component Derivation

| Component | Rule | Example |
|-----------|------|---------|
| `propertyShort` | First 4 chars of property name (uppercase, alphanumeric only) | `575M` |
| `cycleShort` | First char of each word in cycle label + last 2 digits of year | `SO25` (Sept-Oct 2025) |
| `tenantShort` | First 4 chars of tenant display name (uppercase) | `ANIL` |

### Examples

| Property | Cycle | Tenant | Invoice Number |
|----------|-------|--------|---------------|
| 575 McKinney | Sept - Oct | Anil | `INV-575M-SO25-ANIL` |
| 575 McKinney | Sept - Oct | Val | `INV-575M-SO25-VAL` |
| 575 McKinney | Oct - Nov | Divya | `INV-575M-ON25-DIVY` |
| Lakewood Apt | Jan - Feb | Sarah | `INV-LAKE-JF26-SARA` |

Invoice numbers are deterministic (same inputs always produce the same number) and do not require a database sequence.

## 6. API Route

### `GET /api/invoices/[cycleId]`

#### Query Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `tenantId` | `uuid` | No | Specific tenant to generate invoice for. If omitted, generates for all tenants (owner only). |

#### Authentication & Authorization

- Requires authenticated user (Supabase session)
- **Owner**: Can generate invoices for any tenant in their property's cycle
- **Tenant**: Can only generate their own invoice (server validates `tenantId` matches `auth.uid()`)
- **Admin**: Can generate any invoice

#### Response

| Scenario | Status | Content-Type | Body |
|----------|--------|-------------|------|
| Single tenant | 200 | `application/pdf` | PDF binary stream |
| All tenants (owner) | 200 | `application/zip` | ZIP archive containing individual PDFs |
| Cycle not found | 404 | `application/json` | `{ "error": "Cycle not found" }` |
| Unauthorized | 403 | `application/json` | `{ "error": "Not authorized" }` |
| No bills in cycle | 400 | `application/json` | `{ "error": "No bills in this cycle" }` |

#### Response Headers (Single PDF)

```
Content-Type: application/pdf
Content-Disposition: attachment; filename="INV-575M-SO25-ANIL.pdf"
Cache-Control: no-store
```

### Data Fetching Flow

1. Validate session and authorization
2. Fetch billing cycle with property details
3. Fetch all bills in the cycle with their splits
4. Fetch tenant(s) profile and occupancy data
5. Render PDF using `@react-pdf/renderer`'s `renderToStream`
6. Stream response to client

## 7. PDF Rendering

### Technology

- `@react-pdf/renderer` for React-based PDF generation
- Server-side rendering in the API route (Node.js runtime)
- No client-side PDF generation (avoids bundle size impact)

### Component Structure

```
lib/utils/pdf-generator.ts          -- renderInvoicePdf(data) function
components/shared/invoice-pdf.tsx   -- React PDF document component
```

### Invoice PDF Component Hierarchy

```
<Document>
  <Page size="A4" style={styles.page}>
    <InvoiceHeader />        -- Logo, invoice number, date
    <PropertyInfo />         -- Property name, address, owner
    <TenantInfo />           -- Tenant name, email, occupancy
    <CycleInfo />            -- Cycle label, status
    <LineItemsTable />       -- Bills with person-days breakdown
    <SummarySection />       -- Totals
    <Footer />               -- Branding, disclaimer
  </Page>
</Document>
```

### Styling

- Font: Helvetica (built-in, no external font loading)
- Primary color: `#1a1a1a` (near-black text)
- Accent color: `#2563eb` (blue-600, matching FairSplit brand)
- Table header background: `#f1f5f9` (slate-100)
- Borders: `#e2e8f0` (slate-200)
- Page margins: 40pt all sides
- Font sizes: Title 18pt, Section headers 12pt, Body 10pt, Fine print 8pt

## 11. Technical Notes

- `@react-pdf/renderer` runs server-side only; do not import it in client components
- The API route must use the Node.js runtime (`export const runtime = 'nodejs'`), not Edge, because `@react-pdf/renderer` depends on Node APIs
- For the ZIP download (all tenants), use the `archiver` package or similar to stream multiple PDFs into a single ZIP response
- Invoice generation is stateless and on-demand; no invoice records are persisted in the database
- The deterministic invoice number means regenerating the same invoice produces the same number (idempotent)
- Amount conversion from cents to dollars happens in the PDF component layer, not in the data fetching layer
- Consider caching the rendered PDF for a short TTL (5 minutes) in production to avoid redundant generation on repeated downloads
- Maximum expected bills per cycle: ~10; maximum tenants per property: ~20; PDF generation should complete in under 2 seconds

## 12. Out of Scope

- Invoice storage in Supabase Storage (future consideration for audit trail)
- Email delivery of invoices (use notification email with download link instead)
- Custom invoice templates per property
- Invoice payment tracking or "paid" status
- Multi-currency support
- Tax line items or tax calculations
- Digital signatures on invoices
